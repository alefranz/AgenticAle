# Standalone review examples

These examples are acceptance cases for interpreting the [review skill](../skills/review/SKILL.md)
against the [shared round contract](../skills/work/references/rounds.md) and the
[review](../skills/work/references/tasks/review.md) and
[deep-review](../skills/work/references/tasks/deep-review.md) task contracts.
They describe expected coordinator decisions; they are source-interpretation
examples, not live host tests.

| Situation | Expected behavior |
| --- | --- |
| A bare `/review` on a branch with commits and dirty edits | Review the combined current result: the net changes from the merge base to the current working-tree result, including relevant untracked files. A dirty tree never narrows the review to uncommitted changes alone — that would omit the branch's own commits — and nothing is stashed, committed, or discarded. |
| The review context names an explicit scope, for example "only my uncommitted changes" | Review the local changes relative to `HEAD` instead of the merge-base comparison; the recorded baseline is `HEAD` and the endpoint is the working-tree result. No new flag is introduced, and the existing base, focus, `--deep`, and routing-profile behavior are preserved. |
| The base is user-named, resolvable locally, or neither | Use the user-named local base; otherwise the local default from Git metadata and repository conventions; an unavailable or ambiguous base is a question to the user — never a fetch, and no branch, checkout, merge, rebase, or reset. |
| Genuinely conflicting scope instructions | Clarify with the user or reject; never guess a comparison scope. |
| The comparison scope is the default (merge base to working-tree result) | Record the base name, HEAD commit, merge base, the comparison baseline (the merge base), the comparison endpoint (the working-tree result), and the untracked files included in the review in session context before dispatch; the reviewer inspects that exact comparison and verifies its evidence independently. |
| Staged and working-tree contents differ, and untracked files are present | Review the file at its working-tree content — the intermediate staged version is not the target — and include the untracked files where relevant; state the actual comparison and included changes before dispatch. |
| The recorded comparison has no net changes | Report that there is nothing to review and do not dispatch a reviewer when the actual net comparison between the recorded baseline and the working-tree result, including the relevant untracked files, is empty — not when only the commit-range diff or only the local diff is empty. |
| An uncommitted edit cancels the branch's only commit | The commit-range diff and the local diff are both non-empty, but the net comparison from the merge base to the working-tree result is empty: report that there is nothing to review and do not dispatch a reviewer. |
| The review produces findings | Dispatch exactly one fresh reviewer (the review contract, or deep-review with `--deep`), return its findings report to the user, and enter no fix loop: no second reviewer, no fix round, and the shared cycle caps do not apply. |
| A routing profile is selected, unknown, or unavailable | Resolve the route through the same bootstrap Work uses (no new routing key); an unknown or invalid profile is reported before dispatch with the names available for the active runtime, and a removed or unavailable selected profile blocks the dispatch rather than falling back silently. |
| State is created during the activation | The base, recorded comparison, routing record, and report stay in session context only; no handoff, backlog, archive, round ledger, or other operational file is created. |
| Git operations would change the repository | None are made: no commits, pushes, stashes, or branch or remote changes. Before reporting, the branch, `HEAD`, and working-tree result are rechecked: when unchanged, the working tree is left exactly as found; when the checkout or the working-tree result changed during the review, the verdict is scoped to the recorded comparison, that change is stated, and the changed result is never claimed covered. |
| The checkout or working-tree result changes during the review | Never assert the checkout stayed unchanged without the recheck evidence: the verdict covers only the recorded comparison, the report states what changed, and the changed result is not claimed covered. |
| Node is unavailable or the host cannot dispatch a child | Apply the routing contract in context where the fallback is documented; where dispatch itself is unavailable, report the limitation honestly instead of inventing a route, and never claim a clean verdict without evidence. |
| A necessary check is unavailable when the review ends | Never claim a clean verdict: report the established findings together with the missing evidence — the check that could not run and what it leaves unverified — instead of a clean outcome. |
| Work or Autonomous runs after the change | Their existing review and fix gates, budgets and allowances, and state policies apply unchanged: the standalone skill does not activate either workflow or feed it rounds, and addressing the review's findings is a separate request — a same-session `/work` invocation uses the findings and scope directly. |
| A build, install, update, or remove fixture runs | The new skill and its OpenCode command entry are included by the existing ownership rules: they are part of the generated bundle and the install state, an update from a pre-review install adds them without `--replace`, a differing copy collides until `--replace` backs it up, and uninstall removes unmodified owned files while preserving a modified one. |
